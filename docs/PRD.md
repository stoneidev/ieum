# Ieum (이음) 제품 요구사항 문서 (PRD)

> 이 문서는 **현재 버전(v0.2.5)을 기준으로 거꾸로 정리한 PRD**입니다. 처음부터 계획한 문서가 아니라, 만들어진 제품과 그 과정에서 측정하고 결정한 것을 요구사항 형태로 다시 적었습니다.
> 숫자는 `docs/BENCHMARKS.md`의 측정값이고, 측정 환경은 합성 음성(`say`)과 Apple silicon Mac(macOS 26.6)입니다. 실제 회의실에서 잰 값이 아닙니다.
> 작성일 2026-11-08. 이어서 작업하는 사람은 `AGENTS.md`를 먼저 읽으세요.

## 1. 배경과 문제

한국인 직장인이 영어권 동료와 하는 회의(대면, 화상)에서 말은 빠르고, 용어와 이름이 섞이고, 한 번 놓치면 따라가기 어렵습니다. 기존 해결책은 클라우드 자막/번역 서비스인데,
회의 음성을 외부로 보내야 해서 회사 보안 정책에 걸리는 경우가 많고, 지연이 크고, 계정이 필요합니다.

**Ieum은 Mac 한 대 안에서(오프라인) 실시간 자막과 영어 ↔ 한국어 번역을 화면에 띄워 주는 메뉴 막대 앱입니다.**

## 2. 목표와 비목표

### 목표
1. 상대가 영어로 말하면 한국어로 읽고, 내가 한국어로 말하면 영어로 보여 준다(양방향).
2. 말한 내용(녹취)이 **가능한 한 빨리** 보이고, 번역은 조금 뒤에 따라와도 된다.
3. 모든 인식과 번역을 기기 안에서 한다. 계정, 클라우드, 네트워크 요청이 없다(언어 모델 첫 다운로드 제외).
4. 회의 중에 조작하지 않아도 된다. 시작/중지 한 번이면 되고, 화면을 가리지 않는다.
5. 회의가 끝나면 시각이 붙은 기록 파일이 남는다.
6. 상용 제품 수준의 설치, 권한 안내, 서명/공증, 웹사이트, 문서를 갖춘다.

### 비목표 (지금은 하지 않음)
- 화자 구분(Apple Speech가 제공하지 않음), 음성 자체의 저장·재생.
- 영어/한국어 외 언어의 앱 화면(UI) 지원. 인식·번역 언어는 영어·한국어·일본어·중국어(간체)이며 그 밖의 언어쌍은 명령줄 도구만 인식한다.
- 결제/라이선스 키, Mac App Store 배포. (업데이트는 Sparkle 없이 자체 구현, F9-3.)
- 클라우드 번역/인식, LLM 문장 다듬기(CLI의 `--polish` 실험만 존재).
- 실제 회의 영상/통화 앱에 자막을 합성해 내보내기(자막은 내 화면에만 보인다).

## 3. 사용자와 시나리오

**주 사용자**: 영어권 동료가 있는 회의에 참석하는 한국어 사용자(직장인).

| 시나리오 | 설정 | 기대 |
|---|---|---|
| 영어로 진행되는 화상회의를 듣기만 한다 | 영어 → 한국어, 소리 입력 = 시스템 소리 | 상대 영어가 원문과 한국어로 보인다 |
| 대면 회의 테이블에 노트북을 놓고 상대가 영어로 말한다 | 영어 → 한국어, 마이크 | 같은 결과. 멀리서도 읽을 수 있는 큰 자막 |
| 내가 한국어로 발표하고 상대는 영어로 읽는다 | 한국어 → 영어 | 내 말이 영어로 보인다 |
| 서로 번갈아 말한다 | 언어 자동 인식 번역 | 문장마다 언어를 알아내 반대 언어로 번역한다 |
| 번역은 필요 없고 기록만 필요하다 | 한국어 자막 / 영어 자막 | 해당 언어만 나온다 |
| 회의 전에 이름과 용어를 알려 둔다 | 설정 → 용어집 | 잘못 들린 단어가 목록의 철자로 교정된다 |

## 4. 기능 요구사항과 수용 기준

각 항목의 상태는 **구현됨**이며, 수용 기준은 현재 코드와 화면으로 확인한 내용입니다(검증 방법은 §9).

### F1. 입력
- 마이크(기본)와 시스템 소리(ScreenCaptureKit, 화상회의·영상)를 선택한다.
- **마이크 선택**: 설정 → 일반 → 마이크에서 시스템 기본값 또는 연결된 입력 장치(USB 마이크, 스피커폰, 헤드셋 등)를 고른다. 장치는 CoreAudio UID로 저장하고, 저장한 장치가 뽑혀 있으면 기본 입력으로 시작한다(자막이 멈추지 않는다). 실행 중에 바꾸면 다시 시작된다.
  수용: USB 마이크를 고르면 내장 마이크가 아니라 그 장치만 켜진다(CoreAudio `IsRunningSomewhere`로 확인). 선택/폴백 판정은 단위 테스트(`InputDevicesTests`).
- 시스템 소리는 "화면 및 시스템 오디오 녹음" 권한이 필요하며, 없을 때는 설정 열기와 앱 재시작 안내를 보여 준다. 디스플레이가 꺼지면 캡처가 끊긴다는 안내가 나온다.
- 수용: 마이크로 `say` 음성이 인식된다. 시스템 소리로 YouTube 영상이 인식된다.

### F1-2. 통화 (마이크 + 시스템 소리, 나/상대)
- 소리 입력에서 "통화"를 고르면 상대(시스템 소리)는 듣는 언어로, 나(마이크)는 보는 언어로 **각각 따로** 인식하고(`CallEngine`: 인식기 2개), 이벤트에 화자(`me`/`them`)가 붙는다. 번역은 양방향이다(`activeSetup`). 화면의 줄과 기록에 나/상대(`[ME]`/`[THEM]`)가 표시된다.
- 언어를 알아낼 필요가 없어 자동 인식 모드의 약점(확정 전 틀린 언어 글자, 영어 첫 단어 손상, 단어 먼저 보이기 불가)을 피한다. macOS 26 이상.
- 스피커로 들을 때 마이크에 새어 든 상대 목소리: 기본 마이크는 음성 처리(에코 제거)로, 모든 경우 `EchoGuard`(12자 이상인 마이크 결과가 상대의 최근 문장과 거의 같으면 버림; 짧은 대답은 그대로 둔다)로 걸러 낸다. 마이크 인식기가 다른 언어를 내 언어 글자로 옮겨 적은 경우는 글자만으로 가려낼 수 없어서, 기본 마이크의 에코 제거와 헤드폰에 맡긴다(알려진 한계). 특정 마이크를 고르면 음성 처리를 쓰지 않는다(기본 입력에서만 동작).
- 한쪽 입력이 끊기면(디스플레이 꺼짐, 마이크 뽑힘) 통화 전체를 끝내고 이유를 보여 준다. 한쪽 줄이 말하는 중일 때 다른 쪽 문장이 끝나도 그 줄을 지우지 않는다. 방향을 바꾸면 인식기를 다시 시작한다.
- 확인: 시스템 소리 쪽(일본어 → 한국어 번역, 줄마다 "상대" 표시, 기록의 `[THEM]`)은 실기로 확인했다. 인식기 분배·표시·에코 걸러내기·정지·시작 실패 처리는 단위 테스트(`CallEngineTests`, `EchoGuardTests`). **마이크(나) 쪽의 실제 음성은 검증하지 못했다**: 이 Mac은 덮개가 닫혀 내장 마이크가 꺼져 있고 USB 마이크는 스피커 소리를 듣지 못했다. 실제 통화에서 확인이 필요하다.

### F2. 언어 선택 (듣는 언어 / 보는 언어)
- 설정 → 일반 맨 위에 **듣는 언어**와 **보는 언어**, 그리고 **서로 번갈아 말함(언어 자동 인식)** 스위치가 있다. 언어는 영어·한국어·일본어·중국어(간체) 중 어떤 두 개든 고른다. 보는 언어를 "번역 없음 (자막만)"으로 두면 번역 없이 자막만 보인다. 메뉴 막대 메뉴와 ⋯ 메뉴에도 같은 항목이 있다.
- 같은 언어를 두 곳에 고르면 둘이 서로 바뀐다(두 언어가 같아지지 않는다). ⌃⌥L과 ⇄ 버튼은 두 언어를 맞바꾼다(자막만일 때는 듣는 언어가 다음 언어로 넘어간다).
- 이전 모드 5개(한국어→영어, 영어→한국어, 한국어 자막, 영어 자막, 언어 자동 인식 번역)는 이 세 값의 조합이다. 이전 버전의 저장값(koreanToEnglish 등)은 같은 설정으로 옮겨진다.
- 영어를 인식할 때는 영어 억양(미국/호주)을 고른다. 서로 번갈아 말함은 macOS 26 이상에서만 선택할 수 있다.
- 일본어·중국어(zh-CN)는 첫 사용 때 macOS가 인식 모델을 한 번 내려받는다. 자막 바가 "음성 모델을 내려받는 중"이라고 알린다. 이후 오프라인. 단어 사이에 공백이 없어 문장 조각을 공백 없이 잇고, 한글처럼 글자 크기를 보정한다. 용어집 교정은 공백으로 단어를 나누는 영어·한국어에서만 동작한다.
- 수용: 일본어(`say -v Kyoko`)가 정확히 인식되어 한국어로 번역된다. 중국어(`say -v Tingting`)는 인식되어 영어로 번역되고, 한국어 → 중국어도 된다. 한국어 ↔ 일본어 서로 번갈아 말함이 3문장 모두 맞게 판별되어 양방향 번역된다. 판정 로직은 단위 테스트(`MeetingSetupTests`, `SpokenLanguageTests`, `LanguageArbiterTests`).

### F3. 인식 (녹취를 빨리)
- 기본 엔진은 SpeechAnalyzer/SpeechTranscriber(macOS 26), 없으면 SFSpeechRecognizer.
- **단어를 더 빨리 보이기**(기본 켬, 자동 인식 모드 제외): 기존 인식기를 함께 돌려 말하는 중인 문장의 단어를 먼저 보여 주고, 끝난 문장은 SpeechAnalyzer가 확정한다.
- 인식기가 웃음, 박수, 음악 구간에 내는 `,,`, `-...`, `NVI.........` 같은 구두점 찌꺼기는 표시, 번역, 기록에서 걷어 낸다.
- 수용(합성 음성, en-US): 첫 글자 1.01초 → 0.51초, 단어 오류율 3% 유지, 확정 지연 약 0.9초, CPU 약 2.7%, 메모리 약 24MB.

### F4. 번역
- 번역 언어가 Mac에 없으면(지원은 되지만 미설치) 권한 및 설정 점검 창에 **언어 내려받기** 버튼이 나오고, 누르면 macOS 표준 "번역할 언어 내려받기" 창이 열린다(Translation 프레임워크 `prepareTranslation`, macOS 15 이상). 시스템 설정에서 직접 추가해도 된다. 음성 인식 모델(일본어·중국어)은 첫 시작 때 macOS가 자동으로 내려받고 자막 바가 그 사실을 알린다. 확인: 태국어(미설치)로 시스템 창이 뜨는 것을 확인했다(내려받지는 않음).
- Apple Translation(macOS 26.4+, 오프라인). 문장 확정분은 순서대로, 말하는 중인 문장은 최신 것만 번역한다(밀리지 않는다). 요청이 10초 넘으면 건너뛴다.
- 수용: 확정 문장의 번역이 약 0.9~1.5초 뒤에 붙는다. 번역을 쓸 수 없으면 이유와 해결 방법을 오버레이에 보여 준다.

### F5. 오버레이
- **자막 바**: 화면 하단에 항상 위에 떠 있고 포커스를 뺏지 않는다. 줄 수(1~4), 글자 크기 4단계, 배경 4종과 투명도, 번역 표시(원문+번역/번역만)를 조절한다.
  원문(말한 언어)은 위쪽 작은 줄, 번역은 아래 큰 줄. 확정 전 단어는 흐리게, 확정되면 또렷하게. 계속 보이는 상태를 유지한다(흐림 기능 없음).
- **기록 패널**: 시각이 붙은 스크롤 목록, 선택/복사 가능. 문장마다 원문이 위, 번역이 아래. 번역 없는 모드는 그 언어만 나온다.
- **바 컨트롤**: 자막 바 오른쪽 끝에 글자 작게/크게(A), 바/패널 전환, ⋯ 메뉴가 항상 있다(자막이 나오는 중에는 흐리게, 포인터를 가져가면 또렷하게). ⋯ 메뉴에 글자 크기 4단계 하위 메뉴. 이전에는 자막이 나오는 중의 바에 전환 버튼만 있어 메뉴에 닿을 수 없었다.
- **바/패널 전환 버튼**: 바(꺼짐·켜짐)와 패널 헤더에 한 번 클릭으로 전환하는 원형 버튼(⌃⌥D, 메뉴, ⋯ 메뉴, 설정과 같은 동작). 켜진 바에서는 흐리게 표시.
- 꺼져 있을 때는 한 줄짜리 바에 "자막 시작" 버튼과 단축키가 보이고, 켜져 있을 때 패널 헤더에는 "중지" 버튼이 있다.
- 클릭 통과 옵션, 위치와 크기 기억, 모든 Spaces/전체 화면 위에 표시.
- **창 위치(z-order) 선택**: 기본은 항상 다른 창 위(floating). 끄면 일반 창이 되어 다른 창 뒤로 갈 수 있다. 이때 ⌃⌥H는 자막이 다른 앱 창에 가려져 있으면 숨기는 대신 앞으로 가져오고, 메뉴/⋯ 메뉴에 "자막을 앞으로 가져오기"가 나온다. 켜고 끄는 곳: 설정 → 화면, 메뉴 막대 메뉴, ⋯ 메뉴.
- 수용: 한글과 영문이 같은 크기로 보이도록 한글은 0.86배(패널 0.92배). 바 높이는 줄 수에 정확히 맞아 글자가 반쯤 잘리지 않는다.

### F5-4. 답장 도우미 (Instant Reply Prompter)
- 목적: 비원어민이 영어 등으로 답해야 할 때 막히는 말을 즉시 도와준다(듣기를 넘어 말하기). 전역 단축키 ⌃⌥R(기존 ⌃⌥ 계열과 같은 것; ⌥Space는 Option+Space로 nbsp를 입력하는 사용과 겹쳐 피했다), 바 컨트롤·패널 머리글의 말풍선 버튼, ⋯ 메뉴, 메뉴 막대.
- 흐름: 별도 비활성 패널(`ReplyPanelController`, 키 입력만 받고 앱을 활성화하지 않아 회의 창의 포커스를 안 뺏음)이 자막 바 위(자리가 없으면 아래)에 뜬다. 보는 언어로 입력 → `SystemTranslation.makeTranslator(from: 보는 언어, to: 듣는 언어)`(기존 자막 번역의 역방향, 추가 의존성 없음) → 번역을 즉시 표시 → Apple Intelligence가 있으면 이어서 말하듯 다듬은 문장으로 교체(`ReplyPolisher`). 방향 전환 버튼으로 반대로도 번역. 복사 한 번, 최근 답장 3개 다시 복사. 기록은 메모리에만 있고 닫으면 사라진다. 보는 언어가 없으면(번역 없음) 안내만 보인다.
- 다듬기 안전장치(`ReplyHelper.acceptsPolished`): 같은 언어 문자, 질문 유지(질문은 질문으로), 숫자 유지, 이름·요일처럼 문장 안의 대문자 단어 유지, 길이 70% 이상·300% 이하. 어기면 다듬은 문장을 버리고 번역을 쓴다. 실기에서 "질문 → 평서문"과 "결정할 수 없어서" 누락이 실제로 나와 만든 규칙이다. 직역은 항상 보인다.
- 음성 입력: 마이크 버튼으로 한 문장만 인식해 입력창에 넣고 번역한다(자막과 같은 인식 엔진, 12초 제한). 마이크 입력은 이 Mac에서 직접 확인하지 못했다(덮개를 닫아 내장 마이크가 꺼져 있음). 회의에서 소리 내어 말하면 참석자에게 들리므로 입력을 권한다.
- 확인: 단위 테스트 `ReplyHelperTests`, 실기(한국어 문장 5개 → 영어, 복사 → 클립보드, 이전 답장 목록, 화면 공유에서 숨김).

### F5-3. 화면 공유 안전과 자막 바 피하기
- 오버레이 창은 `sharingType = .none`이 기본이다(설정 → 화면 → 화면 공유, ⋯ 메뉴에서 끔). 확인: macOS 26.6에서 ScreenCaptureKit 디스플레이 캡처로 창 위치의 픽셀 한 개만 읽어 비교했다. `.none`이면 창 색이 아니고(보이지 않음), 기본값이면 창 색이다(`Scripts/check-share-safe.swift`, 사용자도 반복 가능). 확인하지 못한 것: macOS 14·15, Zoom/Meet/Teams 실제 공유, 창 하나만 공유(해당 없음). 범위: 자막 바·기록 패널·설정·권한 점검·새로운 기능·업데이트 창(`ScreenShare.protect`)이 숨겨진다. 시스템 대화상자(NSAlert)와 메뉴는 아니다. 부작용: 이 창은 `screencapture -l`로도 찍히지 않으므로 앱 화면 검증은 `-hidesFromSharing NO`로 띄운다.
- 포인터 피하기(`PointerAvoidance`: 반투명+클릭 통과(기본) / 반대편으로 비켜남 / 끔): 자막이 도는 중 자막 바에만 적용, 30Hz로 `NSEvent.mouseLocation`을 읽어(권한 불필요) 바에 6pt 이내로 오면 작동, 28pt 밖으로 나가야 해제(`PointerZone`). 바 오른쪽 170pt(버튼)는 제외. 반투명은 알파 0.18, 떠난 뒤 0.35초 후 복귀. 비켜남은 같은 가로 위치에서 화면 위/아래 반대편(가장자리에서 56pt)으로 0.22초 이동하고 0.8초 안에는 다시 움직이지 않으며, 위치 저장에서는 제외한다. 사용자가 바를 직접 끌면 그 자리가 기준이 된다. 단위 테스트 `PointerAvoidanceTests`, 실기(알파 1.00→0.18→1.00, 버튼 위 1.00, 비켜남 y -229→-1354→-229).

### F9-4. 후원 안내 (Buy Me a Coffee)
- 쓸모를 느낀 뒤 한 번만, 회의가 끝난 다음에만 정중히 묻는다. 3문장 이상 받아 적은 회의를 "실제 회의"로 세어(설정을 바꿔 생기는 재시작은 세지 않는다) 3번째, 12번째, 30번째에 안내하고 그 뒤로는 묻지 않는다. 답: "커피 사주기"(페이지를 열고 감사 인사, 다시 묻지 않음), "나중에"(다음 단계에서), "그만 보기"(영영 안 물음). 설정 → 일반에서 켜고 끌 수 있고, 후원한 사람은 끌 수 없는 상태로 감사 문구만 보인다. 문구는 단계별로 다르고 지금까지 받아 적은 문장 수를 넣는다. 표시: 기록 패널 아래 카드, 꺼진 자막 바 한 줄(폭이 좁으면 ☕ 버튼만), ⋯ 메뉴·메뉴 막대·정보 탭에는 늘 있는 "커피 한 잔 사주기…".
- 개인정보: 횟수는 이 Mac의 UserDefaults에만 저장하고 서버에 아무것도 보내지 않는다. 페이지는 사용자가 누를 때만 브라우저에서 열린다(주소 https://buymeacoffee.com/stoni). GitHub의 후원 버튼은 `.github/FUNDING.yml`. 단위 테스트 `SupportNudgeTests`, 실기(패널·자막 바 카드, 최소 폭 420에서 ⋯ 메뉴 유지).

### F2-2. 상황 (대화 / 회의 / 세미나·강연)
- 쓰는 자리에서 고른다: 기록 패널은 자막을 시작하기 전(비어 있을 때) "지금 무엇을 하시나요?" 세 타일을 보여 주고, 패널 머리글과 꺼진 자막 바에는 상황 이름표(누르면 메뉴, 바가 좁으면 이름표→글자 순으로 사라짐)가 있다. ⋯ 메뉴, 메뉴 막대, 설정 맨 위의 "상황"에서도 고를 수 있다. 상황이 정하는 것: 소리 입력(대화=마이크, 회의=마이크·시스템 소리·통화, 세미나=마이크·시스템 소리), 서로 번갈아 말함(대화는 켠 채 시작, 회의는 선택, 세미나는 없음), 정리의 모양(회의=요약·결정 사항·할 일·남은 질문, 강연=요약·핵심 내용·질문, 대화=요약·핵심 내용·할 일). 고르면 그 상황의 기본값을 적용하고, 쓸 수 없게 된 소리 입력은 기본 입력으로 바꾼다. 이전 버전 설정은 통화 입력이나 서로 번갈아 말함이면 회의/대화, 아니면 회의로 이어받는다(`Scenario.migrated`). 단위 테스트 `ScenarioTests`, 실기(세미나: 서로 번갈아 말함 숨김, 패널 머리글과 탭 이름, 강의 노트 생성).
- 정리 정규화: 상황별 지시문(`MinutesPrompt`: 역할, 항목별 규칙, 할 일의 누가·언제 칸, 예시)과 생성 뒤의 결정적 정리(`MinutesText`, `MeetingMinutes.validated`): 불릿·번호·끝 마침표 제거, "없음" 같은 빈 답 제거, 대소문자·문장부호만 다른 중복 제거, 목록 사이 중복은 할 일 > 결정 > 핵심 > 질문 순으로 한 곳에만, 근거 줄 순서대로 정렬, 담당자·기한은 할 일에만.

### F5-2. 회의 화면: 대화와 회의록
- 기록 패널의 문장은 들린 말(작고 흐림)과 번역(크게) 각각에 언어 표시(EN/KO)가 붙는다. 서로 번갈아 말하는 회의와 통화에서는 문장마다 말한 언어에 따라 번역 언어 표시가 바뀐다(`translationLanguage(forSpoken:)`).
- 패널 위에 "대화 | 회의록" 탭. 회의록 탭은 Apple Intelligence가 있는 Mac에서만 나타난다. 회의 중에는 "회의 중입니다" 안내, 멈춘 뒤에는 "회의록 초안 만들기" 버튼, 만드는 중에는 진행 막대와 중지, 끝나면 요약·결정 사항·할 일(근거 줄 번호와 시각 포함)과 복사·Finder·다시 만들기. 멈추면 대화 탭 아래에 안내 줄이 나오고 누르면 회의록 탭으로 간다. ⋯ 메뉴와 메뉴 막대에도 "회의록 초안…"이 있어 자막 바에서도 닿는다. 새 자막을 시작하면 이전 회의록은 지운다. 확인: 실기(시스템 소리로 영어 4문장 → 패널 → 회의록 탭 → 초안).

### F6. 설정 (일반 / 화면 / 용어집 / 기록 / 정보)
- 일반: 듣는 언어/보는 언어/서로 번갈아 말함, 영어 억양, 소리 입력과 마이크, 로그인 시 열기, 단어를 더 빨리 보이기, 전역 단축키(키캡 표시), 화면 언어(시스템/영어/한국어).
- 화면: 실제 설정이 반영된 자막 바 미리보기, 표시 방식, 줄 수, 글자 크기, 번역 표시, 배경, 투명도, 클릭 통과.
- 용어집: 한 줄에 하나. 입력이 멈추면 1초 뒤 적용. 예시는 입력하면 사라지는 라벨이 붙은 안내.
- 기록: 저장 폴더 선택/열기, 목록(열기, Finder에서 보기, 삭제). 비어 있을 때 안내와 시작 버튼.
- 수용: 모든 문자열이 영어와 한국어로 있다(`tr("en", "ko")`).

### F7. 용어집 교정
- 회의 전에 등록한 이름/용어를, 인식 결과에서 비슷하게 들린 단어를 찾아 목록의 철자로 바꾼다(번역 전). 일반 영어 단어는 시스템 사전(NSSpellChecker)으로 보호해 오교정을 막는다.
- 이유: SpeechTranscriber는 `contextualStrings`를 무시한다(측정함). 용어 포함 문장의 단어 오류율 14% → 4%.

### F8. 기록(스크립트)
- 자막을 시작할 때마다 새 텍스트 파일(`[HH:mm:ss] 문장`, 번역은 `→ …`, 자동 인식 모드는 `[EN]`/`[KO]` 태그)을 `~/Documents/Ieum Transcripts`에 문장 확정 즉시 이어 쓴다.
- 음성은 저장하지 않는다. 저장이 실패하면 자막은 계속 나오고 경고만 보인다.
- 줄의 시각은 **문장을 말한 시각**(듣기 시작한 때 + 음성 안의 시작 위치)이다. 이전에는 인식기가 문장을 내놓은 도착 시각이라 한국어·일본어는 11~19초 늦게 찍혔다. 검증: 일본어 3문장을 실제로 말한 시각(22:58:12, :27, :43)과 기록(:13, :27, :43)이 일치했다.
- **이름 붙이기**: 설정 → 기록의 목록에서 "이름 바꾸기…", 또는 자막을 멈춘 뒤 ⋯/메뉴 막대 메뉴의 "이 회의에 이름 붙이기…". 이름은 파일 이름으로 정리하고(`/`·`:`는 `-`, 최대 80자), 같은 이름의 내보낸 파일(.srt/.vtt/.md, `-2` 변형 포함)도 함께 바꾼다. 이미 있는 이름이면 ` 2`, ` 3`을 붙인다. 하나라도 실패하면 이미 바꾼 것을 되돌린다. 단위 테스트(`TranscriptNamingTests`)와 실기(.txt와 .srt가 함께 `대책회의`로 바뀜)로 확인했다.
- **내보내기**: 설정 → 기록의 목록에서 파일마다 자막 파일(.srt, 번역만 .srt, .vtt)과 Markdown 노트(.md)로 내보낸다. 원본 옆에 새 파일을 만들고 Finder에서 보여 준다. 자막의 시각 0은 자막을 시작한 때이므로, 녹화와 같은 때 시작하면 맞는다. 형식은 단위 테스트(`TranscriptExportTests`).
- **회의록 초안**: 내보내기 메뉴의 "회의록 초안 (.md)". 기기 안 언어 모델(Foundation Models, macOS 26 + Apple Intelligence)이 보는 언어(없으면 듣는 언어)로 요약·결정 사항·할 일을 `<이름>-minutes.md`에 쓴다. 긴 기록은 글자 수로 나눠(CJK는 더 작게) 부분마다 읽고, 부분마다 항목은 6개까지. 모든 항목에 근거 줄 번호와 시각을 붙이고, 존재하지 않는 줄 번호는 버리며, 근거가 없는 항목은 "근거 줄 없음"으로 표시한다(`MeetingMinutes.validated`). Apple Intelligence가 있는 Mac(macOS 26)에서만 제공한다: 구형 macOS나 지원하지 않는 Mac에서는 메뉴 항목과 "새로운 기능" 페이지를 아예 보여 주지 않고, 꺼짐·모델 준비 중·지원하지 않는 언어일 때만 비활성으로 이유와 함께 보인다(`MinutesGenerator.status`). 이름 바꾸기는 `-minutes`, `-minutes-2`도 따라간다. 단위 테스트(`MeetingMinutesTests`)와 실기(한국어 5문장 → 초안, 줄 번호·시각 확인)로 확인했다. **품질은 초안 수준이다**: 이 Mac의 모델은 질문을 결정 사항으로 적거나 누가·언제를 빠뜨리기도 해서, 근거 줄을 읽고 확인하는 것을 전제로 한다.

### F9. 첫 실행과 권한
- 권한 점검 창: 마이크(필수), 화면 및 시스템 오디오(선택), 음성 인식(선택: 단어를 더 빨리), 번역 모델(상태). 메뉴 막대와 설정에서 다시 열 수 있다.
- 권한이 막히면 오버레이/메뉴에 해결 방법이 나온다. 인식기가 스스로 끊기면 최대 2분에 3번까지 자동으로 다시 시작한다.

- **체험해 보기**: 권한 점검 창에서 영어 한 문장(`say`)을 스피커로 재생하고, 같은 파이프라인(영어 → 한국어, 마이크)으로 인식·번역해 결과를 창 안에 보여 준다. 끝나면 저장된 모드/소리 입력을 되돌리고 기록 파일은 만들지 않는다. 마이크가 허용돼 있어야 실행할 수 있다.
  수용: 이 Mac에서 "Hello. This is a test." → "안녕하세요. 이것은 테스트입니다."가 약 15~20초 안에 나온다. 아무것도 들리지 않으면 소리/헤드폰 안내가 나온다.

- 처음 설치(설정 전)에는 보이지 않고, 같은 버전이나 낮은 버전으로 돌아간 경우에도 보이지 않는다. 기록된 버전이 없고 설정을 마친 사용자는 0.2.3에서 온 것으로 본다. 설정 → 정보 → 새로운 기능…에서 다시 연다.
- 동작 줄이기 설정이면 애니메이션을 멈추고 대표 장면을 보여 준다.
- 수용: `-lastSeenVersion 0.2.3`으로 실행하면 5페이지(0.2.8부터 최신순)가, 0.2.7이면 1페이지가 나온다. 버전 비교/선택 로직은 단위 테스트(`WhatsNewTests`)가 있다.

### F9-3. 업데이트 (확인과 설치)
- 하루에 한 번(실행 8초 뒤, 이후 6시간마다 도래 여부 확인) `https://ieum.calmwork.today/latest.json`을 읽는다: 버전, 다운로드 주소(GitHub 릴리스), SHA-256, 크기, 최소 macOS, 한/영 노트. 요청에는 User-Agent `Ieum/버전` 외에 아무것도 없다.
- 새 버전이면 **물어본다**(지금 업데이트 / 나중에 / 이 버전 건너뛰기). 자동 확인에서 새 것이 없거나 서버에 닿지 않으면 아무것도 보이지 않고, 직접 확인(메뉴, ⋯, 설정)은 항상 결과를 보여 준다.
- 설치: 내려받기(진행률) → SHA-256 대조 → DMG 열기, 앱 복사, 닫기 → 같은 개발자 팀 서명, `codesign --verify --deep --strict`, `spctl`(공증), 번들 버전 = 피드 버전 → 실행 파일이 종료되면 스크립트가 옛 앱을 옆으로 치우고 새 앱을 복사, 실패하면 되돌린 뒤 다시 연다. 읽기 전용 위치나 개발 빌드는 확인된 앱을 다운로드 폴더에 두고 안내한다.
- 보안: 다운로드 주소는 https와 GitHub 호스트만 허용(테스트용 localhost 예외는 `-updateFeedURL`을 쓸 때만). 피드가 가짜여도 SHA-256, 팀 서명, 공증을 모두 통과해야 설치된다.
- 설정 → 일반에서 끌 수 있고, 끄면 요청이 없다. 마지막 확인 시각을 보여 준다.
- 수용: 로컬 피드(`-updateFeedURL http://localhost:8765/latest.json -updateCurrentVersion 0.0.1`)로 공증된 0.2.9 DMG를 받아 `/tmp` 복사본이 0.2.9로 교체되고 다시 열린다(약 5초). 체크섬이 틀린 피드는 "공개된 것과 달라서 설치하지 않았습니다"로 거절되고 앱은 그대로다. 판정 로직은 단위 테스트(`UpdateCheckTests`)가 있다.

## 6. 아키텍처 요약

```
마이크 / 시스템 소리 ─ SharedAudioCapture ─┬─ 분석기 입력 (SpeechAnalyzer, ModernSpeechEngine) ──┐
                                           └─ 기존 인식기 (SFSpeechRecognizer, 단어를 더 빨리) ──┤ PreviewingEngine
                                                                                               ▼
                         (자동 인식 모드: 영어·한국어 인식기 2개 → LanguageArbiter)   TranscriptCleaner → VocabularyCorrector
                                                                                               ▼
                                              AppModel ── TranslationPipeline ── 오버레이(바/패널) · ScriptRecorder
```

- `CaptionCore`(라이브러리), `OverlayApp`(앱), `CaptionCLI`, `CaptionBench`, `CaptionCoreTests`. 제품 이름은 앱 산출물(`Ieum.app`)에만 쓰고 내부는 기능 이름을 쓴다.
- `AppModel`이 세션(시작/중지/자동 재시작), 번역 연결, 바/패널 상태를 가진다. UI 상태는 `@MainActor`.
- 동시성: Swift 6 엄격 모드. 번역은 루프당 하나씩만 실행(single-flight), 결과는 epoch로 낡은 것을 버린다.

## 7. 핵심 결정과 근거

| 결정 | 근거(측정/관찰) |
|---|---|
| Swift 네이티브 | Apple Speech/Translation 최신 API가 Swift 전용. |
| 온디바이스 전용 | 회의 보안, 계정 없음, 지연 감소. |
| 듣는 언어 + 보는 언어 두 선택 | 처음엔 "인식 언어"와 "번역 대상"이 따로라 어려워 모드 5개로 합쳤지만, 언어가 4개로 늘자 모드 목록이 커졌다. 그래서 "무슨 말을 듣고 무슨 말로 볼까" 그대로 두 선택으로 되돌렸고(같은 언어를 고르면 서로 바뀌게), 자막만과 양방향은 따로 분리했다. |
| 용어는 인식 후 교정 | `contextualStrings`가 SpeechTranscriber에서 효과가 없음(측정). |
| 멈춤 확정(pauseFinalization) | 한국어 확정 2.59초 → 0.84초, 자동 인식 모드 언어 판별 50% → 100%. **단 영어에서는** 다음 문장 첫 단어를 망가뜨려(WER 7% → 15~20%) 영어 단일 언어 모드에서는 끈다. |
| 두 인식기로 단어를 더 빨리 | SpeechAnalyzer는 1초에 한 번 묶음으로 보고, 기존 인식기는 0.5초부터 단어 단위(0.2~0.3초 간격). 확정은 정확한 쪽이 한다. |
| 번역 재사용 아이디어 폐기 | 중간 번역을 확정에 재사용해도 지연이 줄지 않았다(문장이 확정될 때쯤 텍스트가 달라짐). |
| 구두점 필터 | 웃음/박수에서 나오는 `,,`, `....`를 표시/번역/기록에서 제거. 인식기 출력 자체는 막을 수 없다. |
| 흐림 기능 삭제 | 사용자가 계속 보이는 상태를 원함. |
| Apache-2.0 | 직장에서 자유롭게 쓸 수 있어야 한다는 요구(비상업 라이선스는 직장 사용을 막음). 이름/로고는 NOTICE에서 제외. |
| 가격/결제 보류 | 제품 정책 미정. 구조만 방해하지 않게 둔다. |

## 10. 알려진 한계와 위험

1. **자동 인식 번역 모드의 영어 문장**은 쉼 뒤 첫 단어가 손상될 수 있다(멈춤 확정이 필요해서 끌 수 없음). 단어를 더 빨리 보이기도 이 모드에서는 쓰지 않는다.
2. 웃음/박수/음악이 섞이면 인식기가 문장 앞부분을 놓친다. 필터는 화면만 깔끔하게 할 뿐 되살리지 못한다.
3. 두 인식기가 문장 경계를 다르게 나눠 경계의 단어가 잠깐 앞 문장에 보일 수 있다(확정되면 바로잡힘).
4. 번역 지연(약 1초)은 Apple 번역 엔진의 시간이다. 앱이 줄일 수 없다.
5. 시스템 소리는 디스플레이가 꺼지면 끊긴다.
6. 음성 인식 권한은 "단어를 더 빨리"에만 쓰이는 선택 항목이다. 거부하면 조금 늦게 나온다.
7. 서명 정체성이 바뀌면 사용자 권한이 초기화된다.
8. **서로 번갈아 말함에서 확정 전 한 순간 틀린 언어 글자가 보일 수 있다**: 두 인식기가 같은 확신도로 중간 결과를 내면 먼저 도착한 쪽이 잠깐 앞서고(예: 일본어 음성을 한국어로 옮겨 적은 글자), 확정되면 바로잡힌다. 관측: 일본어 음성에서 "나이스노츠카라"가 한 프레임 보였다. 해결하려면 중간 결과 표시 전에 짧게 기다리거나 언어 판별을 중간 결과에도 적용해야 하는데 지연이 늘어 보류했다.
9. **일본어·중국어 앱 화면은 없다**: 앱 화면은 영어와 한국어뿐이다(`tr("en", "ko")`). 일본·중국 사용자를 위해서는 네 언어 문자열 구조로 넓혀야 한다.

## 11. 다음 후보 (우선순위 순)

> 녹취 조사(`docs/TRANSCRIPTION-RESEARCH.md`, 합성 음성 기준)가 권하는 다음 세 가지: ① 한국어·일본어·중국어의 쉼 규칙 0.7초 → 0.4초(문장마다 확정, 오류율 변화 없음; 실제 말에서 쉼 확인 필요) ② 기록 줄의 시각을 "도착 시각"이 아니라 "말한 시각"으로(한국어는 평균 11~15초 늦게 찍힘) ③ 빠른 결과(fast results)가 문장 끝을 떨어뜨리는 경우의 감지와 기록.


1. 자동 인식 번역 모드에 단어를 더 빨리 적용(영어/한국어 양쪽 빠른 인식기와 판별 로직 필요).
2. 멈춤 확정의 속도 이점을 유지하면서 다음 문장 손상을 없애는 방법(예: 확정 요청 대신 앱 쪽에서 문장 경계를 만들고 접두사만 건너뛰기).
3. 저지연 번역 모델 설치 후 측정, 앱이 설치를 안내할 수 있는지 확인.
4. 실제 회의실 시험과 그 기록.
5. 영어 사용자 가이드, 가격/라이선스 정책 결정, 외부 마이크 선택(입력 장치 선택 UI).
6. 사용자 확대에 가장 큰 영향: 영어·한국어 외 언어쌍(일본어 등). 회의 모드와 언어 처리가 en/ko에 맞춰져 있어 구조 변경이 필요하다. 업데이트 확인(사용자가 누르는 방식)도 후보.
